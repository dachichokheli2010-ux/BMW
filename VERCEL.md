# Deploy Motron to Vercel

Import the GitHub repository or deploy the project folder that contains both
`package.json` and `vercel.json`. The separate `public` and generated `dist`
folders are not complete source projects: they do not include the account,
database and private administrator functions.

## GitHub import

1. Import `dachichokheli2010-ux/BMW` into Vercel, or use its existing connected
   project. Use the repository root as **Root Directory**.
2. Keep **Framework Preset: Other** and Node.js **24.x**. The checked-in
   `vercel.json` supplies **Build Command: `npm run build:vercel`** and
   **Output Directory: `dist/vercel`**. Remove older dashboard overrides pointing
   at `public`, `dist/server`, or `npm run build`.
3. Install the lockfile dependencies, including development dependencies used by
   the build checks. If an Install Command override is necessary, use
   `npm ci --include=dev`.
4. Configure the private server settings below for Production and any Preview
   environment you use, then deploy the current commit.

The earlier `1a8d809` deployment failed because its upload filter removed the
public `.env.example` template needed by a build check. Commit `9ea3d52` fixed
that filter and deployed successfully. A failed earlier deployment remains in
Vercel's history; use the newest commit's build result.

## Deploying the local project folder

Run the Vercel CLI from this project root. A normal source deployment runs the
configured build on Vercel. For example, after connecting the CLI to your own
Vercel account/project:

```sh
npx vercel deploy --prod --archive=tgz
```

The upload filter excludes local `dist`, `.sites-runtime` and `.openai` folders,
local credentials/database files, and unapproved research images. Vercel
rebuilds the release from the retained source. This avoids uploading local
release archives and duplicate builds: the audited working folder previously
retained about 439 MiB for upload, reduced to about 92 MiB after these exclusions.
The exact size changes as approved assets are added.

`npm run build` builds the separate Worker target. `npm run build:vercel`
creates this site's Vercel assets and validates routes, modules and images.
Its `dist/vercel` output is not a `.vercel/output` bundle for `--prebuilt`.

## Private server settings

| Setting | Purpose |
| --- | --- |
| `DATABASE_URL` | Full Neon PostgreSQL connection string; required for accounts and admin storage. |
| `ADMIN_LOGIN_EMAIL` | Email for the separate private `/admin` workspace. |
| `ADMIN_PASSWORD_HASH` | Salted PBKDF2 record generated by `npm run admin:configure`; the plaintext password is not this setting. |

Ignored `.env.local` settings stay on your PC. GitHub pushes and source uploads
do not transfer them into Vercel's server environment. Set them privately in the
Vercel project and redeploy after changes. No public website account grants
administrator access.

After deployment, `/api/auth/session` should return JSON while signed out.
`/api/garage` should return `401`, and `/api/admin/session` should return
`configured: true` with `user: null`. A `configured: false` response identifies
missing or invalid deployed administrator settings; `503` database codes have
separate meanings documented in [DATABASE.md](DATABASE.md).

Local checks verify source/configuration behavior. They cannot change a private
Vercel project's settings without an authenticated project connection.

Vercel documents [Git imports](https://vercel.com/docs/git),
[source exclusions](https://vercel.com/docs/deployments/vercel-ignore), and
[archived CLI uploads](https://vercel.com/docs/cli/deploy#archive).
